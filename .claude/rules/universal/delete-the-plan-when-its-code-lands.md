# Delete a plan file when its code lands — unrun verification gates don't keep it alive

A plan under `.claude/plans/` describes work to do. Once the work is merged the plan is dead weight: delete it in the same change and repair anything that cited it. Gates the plan listed but nobody ran are a reason to run them or file an issue — never a reason to retain the document.

**Why:** An audit of merged pull requests against the plans folder turned up nine implemented-but-retained plans, some months old. Two of those I first proposed keeping as "partially done" purely because their runtime gates had not been exercised, with the code fully in the tree. That over-extends [`runtime-post-conditions-are-gates.md`](runtime-post-conditions-are-gates.md), which makes an unrun gate block *claiming the work is done* — not block *retiring the document*. Retained plans rot in place: status headers reading "open" or "merge-ready, not pushed" for work that shipped, and links to sibling plans that were already deleted.

**How to apply:** When a change implements a plan, `git rm` the plan in the same commit, then grep its filename across `.claude/` and `docs/` and repair the citations. When auditing, the test is whether the artifacts the plan proposed to create exist in the tree — not what the plan's own status header says, since headers are written before merge and never updated afterwards. A genuinely part-done plan keeps only its outstanding parts; delete the sections that landed. If verification is the sole thing left, delete the plan and carry the gate somewhere it will actually be run.
