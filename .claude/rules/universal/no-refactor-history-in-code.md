# Published text serves the cold reader — no history, no unearned length, no environment narrative

Code comments, docstrings, commit messages, PR descriptions, and docs are read cold by someone who wasn't there. Three disciplines, one test: does this clause help a reader who knows nothing about how the text came to be? (The first discipline governs code and docs only — commit messages and PR descriptions exist to describe the change, so they are bound by the other two.)

- **No refactor history.** Describe what the system *is*, not how it got there. Red flags: "previous", "prior", "historical", "absorbed", "refactored from", "no longer", "has been removed" — rewrite to state the current rule directly, or delete. Same for defensive framing ("this is not X — it is Y", "legitimately uses Z"): if the claim isn't being questioned, don't defend it. History belongs in commits and PR descriptions, findable via `git log`.
- **Comments earn their length.** A comment is justified only by what the reader can't get from the code: the *why*, the non-obvious constraint, the gotcha. Cut restatements of the next line, facts the symbol/step/file name already carries, and rationale already stated in another nearby comment; prefer a rough magnitude over false precision (`~60% smaller` beats `1890→713 MB`). A comment much longer than the code it annotates is the signal to compact, and one trailing-line comment beats a multi-line block when one clause suffices. **Zero case:** when an edit's purpose is X (fix a path, move a file), do exactly X — no comment or doc additions as a side effect; adding prose is in scope only when writing prose is itself the task.
- **Environment-neutral.** Repo-public text describes the change generically — no personal-setup narrative (which machine, host, or container runtime hit the problem), and no niche third-party tool names unless the text is specifically instructions for that tool (e.g. a Docker Desktop settings path in a troubleshooting runbook). State the generic mechanism instead ("under emulation", "daemons listening elsewhere").

**Why:** All three disciplines are anchored to direct corrections. History: "No prior versions were ever consumed outside this repo" in a spec doc drew "Why do you add garbage like this?". Length: one session's compactions all hit distinct axes — a 12-line CI-step comment cut to 2, a precise byte figure replaced with a rough percentage — plus three side-effect comment additions during a one-line convention fix, each individually rejected. Environment: a commit framed around the discovery environment (ARM host, specific container runtime) was reframed as plain "optimization/cleanup".

**How to apply:** Before finishing any edit that touches prose, diff-check it against the three disciplines above.
